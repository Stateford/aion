## 2026-11-03 — Lint: LintContext, C201/C202, W101 Reads, Named Messages (Fixes #39)

- **What changed:**
  - New `aion_lint::LintContext<'a>` (interner, `SourceDb`, optional `&dyn aion_arch::Architecture`). `LintRule::check_module(module, design, ctx, sink)` and `LintEngine::run(design, ctx, sink)` take it, following the spec's `arch: Option<&dyn Architecture>`. It has non-panicking helpers: `name`/`try_name`, `signal_name`, `signal_ref_name` (`q[7:4]`, `{a, b}`), `source_text`, `file_text_before` and `source_spelling`, which recovers the user's spelling of VHDL identifiers that the parser folds to lowercase. An unresolvable ident prints `<unknown>` (`UNKNOWN_NAME`), never a raw ID. `aion_lint` now depends on `aion_arch`, which CLAUDE.md allows.
  - Small non-panicking APIs: `Interner::try_resolve` in `aion_common`, and `SourceDb::try_get_file` / `try_snippet` in `aion_source`.
  - **C201** is implemented against `[lint.naming]`: `NamingViolation::new(Option<&NamingConfig>)`, kept by the engine. Messages use the familiar label (`UPPER_SNAKE_CASE`), and the note quotes the exact config line (`parameter = "upper_snake_case"` under `[lint.naming]`), so copying it gives a valid aion.toml. It checks only the categories that are configured (module, signal/port/variable, parameter, constant), uses the source spelling, ignores leading `_` and the scope prefix (`proc.var`), skips escaped identifiers, and suggests a converted name. With no config it reports nothing.
  - **C202** is implemented from source text. A module or entity counts as documented when the first line above it is a `//`/`--` comment or the end of a `/* */` block that starts on a line of its own (a trailing `endmodule /* end */` does not count). Blank lines, `` ` `` directives, `(* *)` attributes and VHDL `library`/`use`/`context` clauses between the comment and the declaration are skipped. `_`-prefixed modules and modules without source text are exempt. Each declaration is reported once, not once per parameter specialization (`is_duplicate_specialization`).
  - **LINT-12 (W101):** `is_signal_read_in_module` now counts `EdgeList` and `SignalList` entries as reads, so the gated-clock and async-reset repros no longer warn. Names starting with `_` (also `proc._x`) are exempt, as the doc and help text said. For a dynamic-index write `mem[addr] <= d`, the IR target is the whole `mem`, so W101 falls back to the assignment's source text and counts the identifiers inside the LHS `[...]`/`(...)` as reads. Concatenation braces are not index brackets, so `{carry, s} = a + b` still reports an unused `carry`. Verilog names are matched case-sensitively (`mem[Addr]` does not hide an unused `addr`); VHDL names are folded to lowercase like the interned names. `LintContext::is_vhdl_source(span)` decides which, and C202 uses it too.
  - **LINT-17:** E105 names the port, the target module and the instance (`missing port connection: port `b` of module `sub` is not connected in instance `u0``) and skips a dangling module ID instead of panicking. W101, W102 and E104 name the signal. W105 lists every missing signal, sorted. W103 and W107 name the assignment target. W103/W107 now walk statements through a small checker struct, which removed W107's `#[allow(clippy::too_many_arguments)]`.
  - Callers updated: `aion_cli lint` and `aion_conformance::finish_pipeline` build a `LintContext` (no target architecture yet). `aion_conformance` gained `full_pipeline_{verilog,vhdl}_with_config`.
- **Tests:** about 50 new tests.
  - `context.rs` (8): name fallback, slice/concat rendering, safe source text, VHDL spelling recovery, whole-word matching.
  - `helpers.rs` (6): edge-list and signal-list reads, LHS operator splitting, `dynamic_index_reads`, specialization detection.
  - C201 (8), C202 (11) and E105 (4), including the raw-ID and dangling-ID cases.
  - W101 (4) covering the issue repros: `_unused`, gclk, `mem[addr]`.
  - W102 (2), E104 (1), W105 (3), W103 (3) and W107 (2) message tests.
  - `Interner::try_resolve` (2) and `SourceDb::try_get_file`/`try_snippet` (3).
  - `lint_detection.rs` gets 15 pipeline tests for the repros, C201 with and without `[lint.naming]`, VHDL spelling, and C202 for Verilog, VHDL and parameterized modules. The two C20x "stub" tests were replaced.
  - 2 conformance-lib tests.
- **Verifier follow-up (same day):** fixed four problems found by an independent review. W101 had stopped reporting unused concatenation targets (the fallback counted `{` as an index). The fallback lowercased Verilog names. C202 accepted a code line with a trailing `/* */` as documentation. The C201 note pointed to `[lint.naming]` but showed a spelling that aion.toml rejects. Added tests: W101 concat target (unit and pipeline, assign and always forms), dynamic index inside a concat, Verilog case sensitivity (unit and pipeline), VHDL case folding, `is_vhdl_source`, C202 trailing block comment (unit and pipeline), and C201 note text plus a round-trip of every config value through `load_config_from_str`. The concat pipeline tests fail when the brace counting is put back.
- **Checks:** `cargo test` passes for `aion_lint`, `aion_conformance`, `aion_cli`, `aion_common` and `aion_source`. `cargo clippy --all-targets -D warnings` is clean for those crates, and `cargo build --workspace --all-targets` builds.
- **Decisions / known gaps:**
  - The dynamic-index read reconstructs reads from source text because AionIR has no dynamic-index target. A proper fix needs a new `SignalRef` variant and touches elaborate, sim and synth, which is out of scope here.
  - Naming checks are opt-in, so the PRD defaults are not applied without `[lint.naming]`. The PRD's TOML example (`"UPPER_SNAKE_CASE"`) does not deserialize, because the config expects `upper_snake_case`.
  - No vendor rule uses `ctx.arch()` yet, and `aion lint` passes no architecture.
- **Phase progress:** Phase 3 status unchanged. All 15 built-in lint rules are now implemented; there are no stubs left.
- **Review follow-up (same day):** fixed three more code-review findings, each first reproduced by a failing pipeline test.
  - W101 dynamic-index fallback counted `(` as an index bracket everywhere, so a VHDL aggregate target `(carry, s) <= ('0' & a) + b;` hid an unused `carry`. A `(` is now an index only when it directly follows a name (identifier, `)` or `]`, whitespace allowed) or sits inside another index; `mem(to_integer(addr)) <= d` still counts `addr`.
  - The same fallback read the base letter and digits of Verilog sized literals as names (`8'd1` → `d1`, `4'hA` → `hA`, `2'b10` → `b10`). It now skips based-literal tails after `'` (optional `s`, base letter, digits/`x`/`z`/`?`/`_`). For VHDL it skips character literals and attribute names after `'`, based literals (`16#FF#`), bit-string bases (`x"0F"`), and in both languages string contents.
  - `LintContext::source_spelling` matched case-insensitively for every language, so `input wire CLK, clk` made C201 check `CLK` for signal `clk`. It now recovers spellings only for VHDL sources (`is_vhdl_source`); Verilog/SV names are returned as interned, which is the case-sensitive match.
  - Tests: 4 pipeline tests in `lint_detection.rs` (VHDL aggregate target, VHDL indexed write, sized literals in an index, Verilog `CLK`/`clk` C201), 6 in `helpers.rs` (aggregate targets, VHDL indexed writes, VHDL literals and attributes, Verilog literal tails, `follows_name`, the literal skippers), 2 in `context.rs` (Verilog/SV case-sensitive, VHDL-only case folding). `cargo test -p aion_lint -p aion_conformance -p aion_cli` and `cargo clippy -p aion_lint -p aion_conformance --all-targets -- -D warnings` pass.
