## 2026-11-04 — Elaborator: VHDL `time` Type and Physical Literals (Fixes #70)

- **Bug:** `constant CLK_PERIOD : time := 20 ns;` (in `examples/blinky_vhdl/tests/blinky_tb.vhd`) failed with E210 "unknown VHDL type `time`" plus W204, because `20 ns` reached the constant evaluator as `20 * <unknown identifier ns>`.
- **IR:** new `Type::Time`, a signed 64-bit count of femtoseconds (`bit_width` = 64). It is a separate type, so it never aliases `signed(63 downto 0)`.
- **Types:** `time` and its subtype `delay_length` resolve to `Type::Time`.
- **Const eval:** `eval_vhdl_time_literal` recognizes physical literals: `20 ns`, `1.5 us`, `2.5e-3 ms`, `1_000 fs`, and a bare unit such as `ns`. It covers every VHDL unit (`fs` … `hr`) and does exact integer scaling with half-up rounding to 1 fs. `eval_vhdl_expr` uses it, so `T / 2` and `T * 100` are plain integer arithmetic. If a constant or signal has the same name as a unit, the name keeps its normal meaning. A value that overflows i64 fs, or a based literal (`16#A# ns`), is an error, not a wrong value.
- **Declarations:** `time` objects keep an `Int` init. A later default can now use an earlier integer or `time` constant (`constant HALF : time := CLK_PERIOD / 2;`). This also makes `constant M : integer := N * 2;` work.
- **Expression lowering:** a time literal used as a value (`t <= 5 ns;`) becomes a 64-bit fs literal instead of E204 "unknown signal `ns`".
- **Tests:** IR: `Type::Time` is distinct and 64-bit, and it round-trips through bincode. Types: `time`/`TIME`/`delay_length`, and an unknown type is still reported. Const eval: unit table, exact scaling and rounding, and rejection of overflow, based or malformed literals; physical literals (int, real, bare unit); time arithmetic; unit shadowing; error on unrepresentable literals. Lowering: 64-bit fs literal, a signal named `ns`, E209 on overflow. End to end: the blinky testbench declarations plus derived constants, and W204 for `3000 hr`.
- **Out of scope (unchanged):** VHDL `wait for` / `after` durations are still dropped when lowering; suspension is #7. `real * time` (`0.5 * T`) is not evaluated. `assert false` in the same testbench still reports E204 "unknown signal `false`". That is a separate bug in expression lowering of boolean literals.
